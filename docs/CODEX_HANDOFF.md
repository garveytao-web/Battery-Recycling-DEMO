# 下一位Codex的执行入口

目标：在本仓库继续完成循电微信小程序验证与发布，不重新设计一套项目，不回退为建议文档。先读 `docs/WECHAT_DELIVERY.md`，再检查当前git状态和变更，不覆盖用户修改。

## 已实现

原H5保持在dist；新原生前端在miniprogram，Node24+SQLite服务在server。完成参数估价、来源报告快照、微信登录交换接口、历史、审核供需、私有意向报价、账户删除、导入CLI与生产检查。

本版真实数据覆盖及限制见交付说明。不要将现有测试通过解释为微信编译或真机通过，不要填造全国前50车型，不要将小三元与软包或某个黑粉品位直接画等号。

## 收到数据后的动作

1. 保存用户原始PDF/截图，逐条保留来源文件名、采集日、报价日期、分类、封装、货物形态、数量、计量单位、总价/单价及费用口径。原件包含个人信息时不得提交到公开仓库。
2. 先形成核对表，与PDF总价复算核对；明显异常隔离。缺失值保持缺失，不为让页面“完整”而补值。
3. 用重量CSV导入。只有核实的范围可填写min/maxWeightKg；单点报告先填同一重量。跨日期/交付条件不可直接混为同一基准。
4. 车型按年款配置与包型号建立来源记录，CSV验证导入。更换过电池的车辆走实际参数入口。
5. 对新增价格来源增加覆盖其单位、有效期、匹配与边界的测试；不要恢复里程/省份折价。
6. 电池之家新行情要保留旧档、更新current和catalog.version，并给过期来源提示。确认分母和交付边界后，再评估是否可以升级为特定范围的采购参考。

## 收到部署配置后的动作

1. AppID、HTTPS API域名写入小程序配置；AppSecret仅由用户在服务器环境填写。
2. 服务端production配置禁止开发登录。保持新API8082与原H58081独立；Nginx只公开HTTPS API，不能开放源码/环境文件/数据库。
3. 运行 `npm test`、`npm run check:mini`、`node check.cjs`；解决实际失败后停止无关扩展。
4. 微信开发者工具导入根目录，编译并真机验收登录、估价、历史、供需审核、两/三账户权限。补充实际截图和错误日志；遇到平台要求按当前官方后台处理。
5. 只有完成对应验收才填release-acceptance.json。执行 `node --env-file=.env scripts/check-release.cjs`，如失败说明具体缺项，不能删掉门槛假装通过。
6. 用户明确授权后才推送/部署/提审。当前只完成本地代码交付，不能宣称已在微信上线。

## 当前必须保留的产品决定

- 主入口是电池参数，车辆匹配可选；知道化学体系和额定kWh即可查看参考范围。
- 每条价格保留元/kg或元/kWh，不未经证明互相换算。
- 无数据不出正常数值；异常状态转核验；原材料价格不能直接乘整包重量。
- 历史只按报告ID读取已保存快照；不能重新计算造成前后金额不一致。
- 用户只读自己的报告；报价联系方式仅报价人和发布者可见。
- 供需有审核、撤下和普通意向报价。无支付、无有效竞拍、无自动成交。

## 代码定位

估价逻辑：server/engine.cjs；身份与业务API：server/index.cjs；数据验证：server/catalog-import.cjs；微信网络和登录：miniprogram/utils/api.js；界面：miniprogram/pages；测试：tests；导入/配置/检查脚本：scripts。
